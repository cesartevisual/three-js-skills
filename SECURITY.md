# Security policy

## Scope and supported versions

Reports are welcome for vulnerabilities in the validation tooling, CI configuration, and instructions that reproducibly cause unsafe operations. The default branch receives fixes. Update to the latest commit before checking whether a problem persists.

Ordinary bugs and feature requests belong in the issue tracker. Vulnerabilities in Three.js, an agent host, or another dependency should go to that project's maintainers unless this repository introduces the issue.

## Report a vulnerability privately

Use [GitHub's private vulnerability reporting form](https://github.com/cesartevisual/threejs-skills/security/advisories/new). Private vulnerability reporting is enabled for this public repository; signing in to GitHub is required to submit a report.

Include the affected commit, relevant environment, reproduction steps, impact, and any proposed mitigation. Provide only the information needed to reproduce the problem, and redact credentials and private project data.

Do not publish vulnerability details in a public issue. If the private reporting form is unavailable, open an issue asking the maintainer to restore it without disclosing the vulnerability. No guaranteed response time is established yet.

For non-security bugs, use the issue tracker. For conduct concerns, follow the [code of conduct](CODE_OF_CONDUCT.md); the vulnerability form is for security reports.

## Fixes and disclosure

Maintainers should confirm reproducible reports, coordinate fixes and disclosure with the reporter, and document relevant fixes in the security advisory. Avoid sharing sensitive details before a mitigation is ready.

See [GitHub's vulnerability reporting documentation](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository) for feature availability and setup.
